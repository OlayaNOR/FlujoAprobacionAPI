# ADR-005: Criterio entre 409 y 422

## Contexto

Ambos códigos sirven para peticiones bien formadas que no se pueden cumplir, y usarlos sin criterio deja al cliente sin saber si reintentar tiene sentido.

## Decisión

- **409:** la petición sería válida, pero el estado actual del recurso no la permite. Enviar una solicitud cancelada o dos escrituras concurrentes. Consultar el recurso de nuevo puede cambiar lo que el cliente decida.
- **422:** el contenido de la petición viola una regla, sin importar el estado del recurso. Un periodo en el pasado o una moneda distinta de la base. Repetirla igual siempre va a fallar.
- **400:** ni siquiera se puede interpretar: JSON mal formado, un tipo incorrecto o un campo fuera de formato.

Enviar una solicitud cuyo solicitante no tiene jefe es 422, aunque dependa de otros datos: no cambia el estado de la solicitud, y lo que hay que corregir es la configuración.

## Consecuencias

- Las excepciones del dominio se mapean una a una: `TransicionInvalidaException` y `SolicitudNoEditableException` a 409, `ReglaNegocioException` a 422.
- El 409 de transición incluye `estadoActual`, para que el cliente no tenga que hacer otra consulta.
